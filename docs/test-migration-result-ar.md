# نتيجة تطبيق Prisma Migrations على قاعدة الاختبار

التاريخ: 15 أكتوبر 2026. فرع العمل: `codex/phase-one-news-review`.

## نطاق الموافقة والهدف

نُفّذ التطبيق على قاعدة `nyba_test` الخاصة بمشروع الاختبار `new-york-bel-arabi-test`، وفق مطابقة المضيف ومعرّف المشروع التي أكدها المستخدم سابقًا في Neon Console. استُخدم DATABASE_URL من `.env.test.local` فقط، ولم يُقرأ `.env` لاختيار الاتصال. تحققت الدالة المحلية من اسم القاعدة والمضيف وتأكيد المشروع والاتصال المباشر وTLS، ثم أكد استعلام `current_database()` اسم `nyba_test` في معاملة قراءة فقط قبل الكتابة. لم يُجر استعلام Neon API لإثبات ملكية المضيف؛ الاعتماد في ذلك على المطابقة اليدوية المؤكدة.

## السجل قبل التطبيق والترتيب

أكد الفحص الأول عدم وجود جدول سجل Migrations أو جدول أخبار أو جداول تطبيق غير متوقعة في public. القاعدة فارغة وعدد الأخبار صفر. عُرض ترتيب الملفات للمستخدم قبل التنفيذ:

1. `20261012183054_init_articles`: إنشاء Article.
2. `20261012184936_add_article_fields`: إضافة borough وcategory وcolor وsummary.
3. `20261015135634_unique_article_source_url`: إنشاء الفهرس الفريد على sourceUrl.
4. `20261015160000_original_text_and_review`: إضافة حقول الأصل والمراجعة والاعتماد وrevision.

لم توجد Migrations غير متوقعة. أعاد المشغّل فحص الهوية والسجل والأعمدة وعدد الأخبار قبل استدعاء عملية التطبيق.

## وسيلة التطبيق المعزولة

أضيف `scripts/test-migrations.cjs` بوضعين محددين: inspect للقراءة فقط وapply للتطبيق المعتمد. لا يُشغّل تلقائيًا مع اختبارات المشروع.

في وضع apply ينسخ المخطط وملفات Migration الأربعة إلى مجلد مؤقت مستقل. يبدّل اسم متغير اتصال المخطط المنسوخ إلى NYBA_TEST_DATABASE_URL ويجهز Prisma config خاصًا لا يستورد dotenv، ثم يشغّل `prisma migrate deploy` من المجلد المؤقت ببيئة صغيرة لا ترث DATABASE_URL أو أسرار التطبيق. يُمرّر اتصال الاختبار المقروء والمتحقق منه فقط. لا يستخدم prisma.config.ts الأصلي أو .env الخاص بالمشروع. تُحجب مخرجات Prisma الخام التي قد تتضمن تفاصيل الاتصال، ويُحذف المجلد المؤقت بعد الانتهاء.

تعذّر الفحص الأول داخل عزل الشبكة؛ نجح الفحص ثم التطبيق بعد السماح بتنفيذ الاتصال خارج قيد الشبكة. لم تستخدم أوامر db push أو migrate dev أو migrate reset.

## فحوص ما بعد التطبيق

- سجل Prisma يحتوي الملفات الأربعة بالترتيب، وكل ملف مكتمل بلا rollback، مع تطابق SHA-256 لملف SQL المحلي وعدد خطوات تطبيق موجب.
- لا توجد ملفات محلية معلقة بعد اكتمال الملفات الأربعة المتوقعة.
- أسماء أعمدة Article تطابق المخطط المتوقع: الحقول الأصلية مع الأعمدة الثمانية الجديدة، دون أعمدة إضافية غير متوقعة.
- originalTitle وoriginalSummary وoriginalContent وreviewedBy وapprovedBy من نوع text وتقبل NULL.
- reviewedAt وapprovedAt من نوع timestamp without time zone وتقبل NULL.
- revision من نوع integer ولا يقبل NULL، وقيمته الافتراضية 0.
- فهرس Article_sourceUrl_key موجود وفريد.
- لا توجد قيم revision فارغة.
- عدد الأخبار قبل التطبيق 0 وبعده 0؛ لم تُدرج بيانات تجريبية أو تُحذف أخبار.
- أُغلقت اتصالات الفحص بعد الانتهاء.

## حدود النتيجة والخطوة التالية

نجاح إنشاء المخطط على قاعدة اختبار فارغة لا يثبت بعد سلامة ترقية أخبار قديمة موجودة أو سلوك الواجهة والترجمة والمراجعة عمليًا. تلك التجارب تحتاج مرحلة منفصلة مع بيانات تجريبية وموافقة على إدخالها. لم تُشغّل خدمة الترجمة أو يستورد RSS حقيقي في هذه المهمة.

لم نفتح اتصالًا بالإنتاج ولم نغير بياناته. لم نعرض رابط اتصال أو كلمة مرور. لم يحدث Git push أو Merge أو Deploy، ولم تُعدّل ملفات SQL أثناء التطبيق. توقف العمل بعد الفحص والتقرير؛ لا توجد موافقة ضمنية لتطبيق الإنتاج أو إعادة تشغيل apply.
