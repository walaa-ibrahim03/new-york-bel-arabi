# تقرير المرحلة الأولى

الفرع: `codex/phase-one-news-review`.
لم يُجر أي اتصال بقاعدة الإنتاج أو تعديل بياناتها، ولم يُطبّق أي Migration أو db push أو migrate dev. لم يُنفّذ Push أو Merge أو Deploy.

## التغييرات والملفات

- `prisma/schema.prisma` و`prisma/migrations/20261015160000_original_text_and_review/migration.sql`: أصل العنوان والملخص والمحتوى في حقول اختيارية، وحقول اختيارية للمراجعة والاعتماد وهوية المدير ووقتهما، ورقم نسخة يبدأ من صفر. Migration إضافية فقط دون حذف أو تحديث أخبار قديمة.
- `lib/import-rss.ts`: حفظ النص المصدر منفصلًا، رفض العنوان الطويل والملخص المفرط والتاريخ غير الصالح والرابط غير الصالح، مع استمرار تجاوز التكرار عبر قيد الرابط الفريد. يبقى الملخص المعروض ضمن حد 500 حرف، بينما الأصل يحتفظ بالملخص المستورد. RSS يوفر مقتطفًا وليس بالضرورة المقال الكامل.
- `lib/rss.ts`: السماح بالمصادر المعرّفة فقط، مهلة 15 ثانية، منع إعادة التوجيه، وتنظيف الفراغات.
- `lib/article-policy.ts`: التحقق من الحقول والمعرّفات وروابط HTTP/HTTPS العامة دون بيانات دخول أو عناوين IP أو أسماء محلية، وسياسة النشر.
- `lib/categories.ts` و`lib/news-sources.ts`: قائمة تصنيفات مشتركة وأسماء بديلة للتصنيفات التاريخية. لا إعادة كتابة جماعية لبيانات التصنيفات. تبقى «السكن» و«سكن واقتصاد» مدعومتين دون دمج قد يفقد المعنى.
- `app/page.tsx`: مطابقة التصنيفات القديمة عبر الأسماء البديلة وإظهار سكن واقتصاد ضمن قسم الخدمات المرتبطة بالسكن.
- `app/admin/actions.ts`: مسودة → قيد المراجعة → معتمد → منشور، وكل انتقال محمي بتوثيق المدير وحالة الخبر على الخادم. النشر يتطلب اعتمادًا مسجّلًا. تستخدم الانتقالات رقم النسخة لمنع تعارض الكتابة. يمكن إعادة الخبر للمسودة أو إلغاء نشره.
- `app/admin/editor-actions.ts`: كل تعديل يعيد الخبر للمسودة ويلغي الاعتماد وتاريخ النشر، مع منع حفظ نسخة قديمة. حفظ الترجمة لا يكتب حقول الأصل. الترجمة تستخدم الأصل فقط. لا يُسمح بتغيير مصدر خبر ذي أصل محفوظ حتى لا ينفصل النص عن مصدره.
- `app/admin/ArticleForm.tsx`: عرض الأصل للقراءة، وإرسال رقم النسخة عند الحفظ، وقائمة التصنيفات المشتركة مع الاحتفاظ بأي تصنيف قديم غير معروف. الأخبار القديمة بلا أصل قابلة للتحرير اليدوي؛ الترجمة الآلية معطلة لها بدل اعتبار العربية أصلًا إنجليزيًا.
- `app/admin/ArticlesDashboard.tsx`: مراحل وأزرار وفلاتر المراجعة والاعتماد، ومصادر RSS من القائمة المشتركة. ميزات الحذف الموجودة بقيت في التطبيق؛ لم تُستدع أثناء العمل.
- `tests/phase-one.cjs` و`package.json`: اختبارات محلية بأدوات وهمية للقاعدة والتوثيق، وتمنع تحميل الاعتماديات الخارجية غير المصرح بها. الأمر `npm run test:phase-one`.

## حدود مقصودة

- المدير الحالي يستطيع الإرسال للمراجعة والاعتماد؛ لا يوجد شرط مراجع ثانٍ لأن نظام الصلاحيات الحالي قائم على مدير واحد.
- الأخبار المنشورة سابقًا تبقى منشورة دون ملء اعتماد تاريخي مصطنع. عند تعديلها أو إعادة نشرها تمر بالمسار الجديد.
- الأصل المفقود سابقًا لا يُستعاد تلقائيًا ولا نملأه بنص يحتمل أنه ترجمة.
- التحقق من الروابط بنيوي، وليس فحص توفر صفحة المصدر أو إثبات صحة الخبر. مطابقة المحتوى والوقائع والمصدر مسؤولية المراجعة البشرية. لا تُجلب روابط المقالات أثناء التحقق.
- الكود الجديد يحتاج أعمدة Migration قبل تشغيله على قاعدة حقيقية. توافق البيانات القديمة لا يعني إمكان تشغيل الكود الجديد على المخطط القديم.

## خطة تطبيق لاحقة — تحتاج موافقة مستقلة

1. مراجعة SQL وسجل Migrations المطبق فعليًا، وتجهيز نسخة احتياطية أو نقطة استعادة متحققة. لم نفحص القاعدة في هذه المهمة.
2. إنشاء قاعدة اختبار منفصلة ببيانات تجريبية، وضبط بيئة الاختبار عليها فقط.
3. بعد الإذن بتغيير قاعدة الاختبار، تطبيق Migration فيها والتحقق من بقاء الأخبار القديمة وتصنيفاتها وروابطها وحالتها، ومن سلامة جميع المراحل والترجمة والحفظ المتزامن.
4. التأكد من نجاح البناء واختبار الواجهة وتسجيل الدخول وRSS والترجمة في بيئة الاختبار.
5. بعد موافقة صريحة على الإنتاج، تطبيق Migration الإضافية على الإنتاج أولًا في وقت مناسب؛ الكود القديم يتجاهل الأعمدة الجديدة. يستخدم `prisma migrate deploy` حينها فقط بعد التأكد من أن جميع Migrations المعلقة مقصودة، لأنه يطبقها جميعًا.
6. بعد موافقة النشر، نشر الكود الجديد ومراقبة التحرير والاعتماد والنشر. قد تأخذ إضافة الأعمدة قفلًا قصيرًا؛ تحدد مهلة قفل مناسبة وتُراقب العملية.
7. عند التراجع، استعادة إصدار التطبيق السابق مع إبقاء الأعمدة الجديدة والبيانات الأصلية. لا تحذف الأعمدة ولا تنفذ Migration عكسية تُفقد البيانات.

## نتائج الفحوص

- Prisma generate: نجح محليًا؛ توليد عميل فقط دون اتصال بقاعدة البيانات.
- TypeScript (`tsc --noEmit`): نجح.
- ESLint للملفات المعدلة: نجح.
- خمسة اختبارات محلية: نجحت، وتغطي التصنيفات والروابط ومسار الخادم والصلاحيات وتعارض النسخ والاستيراد وفصل الأصل وإلغاء الاعتماد عند التحرير.
- `git diff --check`: نجح.
- بناء Turbopack: تعذّر بسبب منع فتح منفذ محلي (`Operation not permitted`)، وتكرر السبب عند إعادة المحاولة. استُبدل DATABASE_URL بقيمة غير صالحة أثناء البناء لمنع استخدام Neon.

- بناء Webpack البديل: نجح بالكامل (`next build --webpack`) بما فيه TypeScript وتوليد الصفحات. احتاج إعادة محاولة للسماح بتحميل خط Cairo من Google Fonts، وبقي عنوان قاعدة البيانات معطّلًا. لم تُختبر الواجهة مع قاعدة حقيقية أو تُستدعَ خدمة الترجمة أثناء الاختبارات.
