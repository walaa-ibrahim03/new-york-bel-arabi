# تطوير إضافة الأخبار اليدوية والجلب من RSS

هذه نسخة عمل محلية على codex/phase-one-news-review. لم تُنشر، ولم تتغير قاعدة الإنتاج أو الاختبار أو إعدادات Vercel أو Google OAuth أو DATABASE_URL.

## الواجهة والمسار التحريري

- بطاقتان واضحتان: «إضافة خبر يدويًا» و«جلب الأخبار تلقائيًا»، بتصميم RTL وشبكة تتحول لعمود واحد على الهاتف.
- النموذج الحالي أُعيد استخدامه: العنوان والقسم والملخص والمحتوى والمنطقة ورابط المصدر، مع إضافة اسم المصدر ورفع صورة اختياري ومعاينة.
- المعاينة تعرض النص كنص آمن، دون HTML خام، ولا تحفظ أو تنشر. التعديل على الحقول يُخفي المعاينة القديمة حتى تحديثها.
- زران منفصلان: الحفظ كمسودة، والحفظ والإرسال للمراجعة. يتحقق الخادم من intent ولا يقبل APPROVED أو PUBLISHED من النموذج. تظل الموافقة والنشر عبر إجراءات المراجعة القائمة؛ التعديل يلغي الاعتماد السابق ويحافظ على الأصل الإنجليزي وشرط revision.
- حالات الخطأ المتوقعة تظهر في النموذج برسائل آمنة. الحقول النصية والقسم والصورة مضبوطة بالحالة، فلا تضيع قيمها عند رجوع خطأ الحفظ. تحويل Next.js بعد النجاح يبقى محفوظًا.
- اسم المصدر اختياري في مخطط البيانات للأخبار القديمة، ومطلوب عند إنشاء خبر يدوي جديد. لا يُعاد ملء الأخبار القديمة أو تغييرها تلقائيًا. يظهر الاسم بجوار رابط المصدر في صفحة الخبر، مع البديل القديم عند غيابه.

## الصور

تكامل خادمي جاهز مع Vercel Blob، دون إنشاء Store أو استخدام Token حقيقي في الفحوص. لا تخزين في مجلد public أو قرص Vercel المؤقت، ولا تخزين للصورة داخل PostgreSQL.

- صلاحية المدير ووضع الكتابة مطلوبان؛ الحارس يتحقق من هوية الاتصال قبل التخزين دون فتح اتصال قاعدة لهذا الغرض.
- JPEG وPNG وWebP فقط، بحجم أقصى 2 MiB؛ يرفع Next سقف طلب Server Action إلى 3 MB لاحتواء الملف والغلاف.
- تُفحص البصمة الثنائية والنوع الفعلي عبر Sharp؛ تُرفض SVG والملفات المتنكرة والصور المتحركة أو الأكبر من 16 مليون بكسل، ثم تُفك وتُعاد إلى WebP بأبعاد لا تتجاوز 1920×1920 دون تكبير.
- إزالة EXIF/GPS تلقائية بإعادة الترميز؛ اسم تخزين عشوائي، دون اسم الملف الأصلي، والتحقق من مضيف Blob المرتجع. لا تُطبع مفاتيح أو رسائل مزود الخدمة الخام.
- الصور Public ويمكن لمن يملك الرابط قراءتها، حتى لو لم يُنشر الخبر بعد؛ تظهر هذه المعلومة في النموذج. لا صور خاصة أو صور بلا إذن. الصورة لا ترتبط بالخبر إلا عند حفظه.
- إلغاء النموذج بعد رفع صورة قد يترك ملفًا غير مرتبط. لا حذف تلقائي للصور؛ خطة تنظيف الملفات غير المرتبطة تحتاج قرارًا مستقلًا يحمي الصور المستخدمة.
- المعاينة المحلية المعزولة ترفض التخزين الخارجي حتى لو أُمررت لها مفاتيح بالخطأ، والمشغّل لا يرث مفاتيح الإنتاج.

تفعيل الرفع لاحقًا، بموافقة منفصلة:

1. إنشاء Public Blob Store المناسب واختيار خطة/حدود تكلفة مناسبة؛ لم يحدث ذلك هنا.
2. إعداد BLOB_READ_WRITE_TOKEN كسرّ خادمي، وNYBA_PUBLIC_BLOB_HOST بمضيف المتجر، وNYBA_IMAGE_UPLOADS_ENABLED=true. لا تُرسل القيم السرية في المحادثة أو Git.
3. اختبار تكامل التخزين على ملف تجريبي مصرح به بعد إعداد الخدمة، دون تغيير أخبار حقيقية. هذا الاختبار الخارجي لم يُنفذ؛ الاختبارات الحالية تستخدم مزود تخزين وهميًا مع معالجة صور حقيقية داخل الذاكرة.

راجع [توثيق Vercel Blob](https://vercel.com/docs/vercel-blob/using-blob-sdk) و[ضوابط Sharp](https://sharp.pixelplumbing.com/api-constructor/).

## RSS والأذون

أُبقي RSS Parser الحالي وحدود الجلب والتصنيف بالكلمات المفتاحية وحفظ الأصل ومنع التكرار بقيد Prisma. أُضيف حفظ اسم المصدر من إعداد المصدر الموثوق، والتحقق من نطاق رابط الخبر، وإزالة معلمات التتبع/fragment عند مقارنة الروابط. تُقارن الروابط القديمة دون تعديلها، ويبقى القيد الفريد خط الدفاع عند تزامن استيرادين.

الجلب يتم عند طلب المدير، ولا توجد Cron أو جدولة جديدة. لا سحب للمقالات الكاملة أو الصور، ولا OpenAI ضمن الاستيراد، ولا نشر تلقائي: النتائج DRAFT فقط. تعرض الواجهة عدد المسودات والمكرر/غير الصالح والأخبار خارج الأقسام المستهدفة.

وجود RSS ليس تصريح إعادة استخدام. جميع المصادر الحالية محفوظة في القائمة لكنها تنتظر إذنًا متوافقًا مع الاستيراد الآلي والترجمة والعرض بهذه الآلية:

- [WNYC/Gothamist](https://wnyc.org/terms/): شروط RSS تذكر الاستخدام الشخصي غير التجاري وطلب الإذن للاستخدامات الأخرى.
- [THE CITY](https://www.thecity.nyc/republishing/): التعليمات تمنع إعادة النشر الآلي والتعديل إلا ضمن استثناءات محددة، وتطلب نسب العمل وشروطًا أخرى. لم يُعتبر ترخيصها العام إذنًا لهذا المسار الآلي أو الترجمة.
- [amNewYork](https://www.amny.com/terms-of-use/): شروط المحتوى وRSS تتضمن قيودًا على إعادة الاستخدام التجاري والتوزيع.

لا استنتاج بأن هذه المواقع منحت إذنًا للمشروع. بعد مراجعة إذن يغطي الاستخدام المطلوب ونسب المحتوى، يُحدّث مسؤول المشروع permission في lib/news-sources.ts: automaticImport وtranslation وreference. المرجع وصف عام غير سري؛ هذا الملف يدخل حزمة الواجهة، فلا توضع فيه مفاتيح أو اتفاقيات خاصة. إذا فرض الإذن نسب مؤلف أو شروطًا إضافية غير مدعومة، يجب تنفيذها أولًا وعدم تفعيل المصدر بمجرد وجود RSS.

الخادم يرفض المصدر غير المعتمد قبل الشبكة أو قاعدة البيانات حتى لو جرى تجاوز الواجهة. زر المصدر غير المعتمد معطل مع رابط شروطه وسبب واضح. وتُمنع ترجمة أصل من مصدر معروف إذا لم يعد إذنه معتمدًا. لا إرسال بريد للمصادر أو قبول اتفاقيات أو شراء تراخيص في هذه المهمة.

## Migration وخطة النشر اللاحقة

جهّزنا فقط 20261016160000_article_source_name: إضافة sourceName TEXT اختيارية. لا DROP أو UPDATE أو Backfill، ولا تغيير في الأخبار أو الأعمدة القديمة. تحديث Prisma Client أثناء البناء محلي فقط، وليس Migration.

قبل النشر، وبعد موافقة صريحة مستقلة:

1. تجربة Migration الخامسة على قاعدة الاختبار المؤكدة، ثم فحص التوافق مع الأخبار القديمة؛ سكربت اختبار Migrations مُحدّث لمعرفتها ولم يُشغّل هنا.
2. إثبات هدف الإنتاج بالحارس وفحص السجل والبصمات، وتجديد/مطابقة النسخة الاحتياطية، وتجميد التحرير عند التطبيق.
3. تطبيق Migration الإضافية وحدها عبر migrate deploy على الاتصال المؤكد، والتحقق من بقاء الأعداد والبصمات وnullable sourceName؛ لا db push أو migrate dev/reset.
4. إعداد التخزين بعد الموافقة وتوثيق أذون المصادر قبل تفعيلها. يمكن نشر النموذج دون Blob مع بقاء رابط الصورة القديم، والجلب يظل متوقفًا للمصادر غير المعتمدة.
5. نشر مرحلي مع الحارس والتحقق من MATCH قبل تحويل النطاق. الرجوع إلى الكود السابق ممكن مع إبقاء العمود الاختياري؛ لا استعادة تلقائية لبيانات أقدم ولا حذف العمود.

لا تُشغّل المعاينة الجديدة على قاعدة اختبار لم تُطبّق عليها الإضافة بعد؛ نموذج التحرير يحتاج العمود الجديد. لا صلاحية لتطبيقها ضمن هذه المهمة.

## الاختبارات والحدود

النتائج: `npm run test:phase-one` نجح 42/42، و`npm run typecheck:offline` و`npm run lint` نجحا، و`npm run build:check` نجح ببناء الإنتاج الفعلي وتوليد CSS. فُحصت أيضًا نسخة HTML ثابتة من المكونات وCSS الفعلي في المتصفح على عرض 390px لكل من اللوحة والنموذج، دون تجاوز أفقي. هذا فحص تصميم ببيانات وهمية، وليس ادعاء اختبار دخول أو تخزين حي.

الاختبارات دون شبكة وعلى بيانات خيالية في الذاكرة؛ لا اتصال بأي قاعدة أو Blob أو Google OAuth أو OpenAI أو RSS حقيقي. تشمل المسودة/المراجعة ورفض النشر المباشر، والصلاحيات ورفض القراءة فقط، وحفظ الأصل وإبطال الاعتماد، وأخطاء النموذج، وبنية RTL ومعاينة XSS، وصورًا فعلية مصطنعة لإثبات إزالة EXIF ورفض التزييف والحجم والبكسلات، وحجب التخزين غير المصرح، وأذون RSS والتكرار والتصنيف ونسب المصدر، وكون SQL إضافيًا فقط.

ظهرت 8 تحذيرات npm audit عالية موروثة من شجرة ESLint وPrisma/config وملحقاتها؛ إصدارات الحزم المعنية مطابقة للـCommit السابق، وليست من حزمتَي الرفع الجديدتين. بعضها dev وبعضها devOptional/peer. لم نطبق npm audit fix --force لأنه يقترح تغييرات رئيسية غير متوافقة؛ تبقى مراجعتها ومعالجتها بندًا قبل النشر الفعلي، ولا يُدّعى خلو المشروع من التحذيرات.
