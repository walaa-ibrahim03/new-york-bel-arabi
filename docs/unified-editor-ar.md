# توحيد إعداد الخبر وحماية النشر

واجهة /admin تستخدم مكوّن إعداد خبر نفسه في /admin/quick: اختيار مصدر للمتابعة المباشرة، رابط المقال، وقائع يكتبها المحرر، تجهيز بالعربية، معاينة قابلة للتعديل، حفظ مسودة أو نشر بتأكيد واحد. لا جلب مقال أو صورة، ولا تغيير أذونات المصادر. المحرر المطول والجلب القديم ودليل المصادر داخل «خيارات إضافية» المغلق افتراضيًا. مسارات التحرير القديمة باقية.

سياسة lib/publication-policy.ts موحدة عند كل انتقال إلى PUBLISHED في المحرر أو مسار الاعتماد القديم. تتطلب غلبة العربية بنسبة 65% من الحروف على الأقل في كل من العنوان والملخص، وعنوانًا من كلمتين على الأقل. تسمح بالأسماء والاختصارات الإنجليزية داخل نص عربي؛ حرف عربي داخل نص إنجليزي لا يمر. الملخص 40–80 كلمة؛ يقبل 8–39 كلمة فقط عند تأكيد المدير صراحة محدودية الوقائع. الرسائل توضح سبب الرفض. ليست هذه القواعد ضمانًا آليًا لدقة الوقائع؛ تبقى مراجعة المدير شرطًا. تظل المسودات الإنجليزية والأصل الداخلي مسموحين، ولا يمر النشر بطلب Server Action مباشر متجاوزًا الفحص.

لا إعادة تصنيف أو تعديل أو إلغاء نشر لأي سجل قديم؛ الخبران 26 و42 لا يُلمسان. لا مرشح عرض جديد يخفي الخبر المنشور القديم. الأصول محفوظة كما في المسارات السابقة ولا يعاد توليدها عند تعديل العربية.

الحذف المستقبلي يسجل JSON صغيرًا في سجلات الخادم: event وarticleId وactorRole ثابت admin وoutcome وat فقط. لا بريد أو اسم أو نص أو رابط أو أسرار، ولا أخطاء Prisma خام. يسجل المحاولة والنجاح/الفشل، وفشل مصرف السجل لا يحول حذفًا ناجحًا إلى فشل معلن. هذه أدلة تشغيلية best-effort، ليست سجلًا دائمًا أو ذريًا مع الحذف؛ تعتمد على احتفاظ المنصة بسجلات runtime. سجل مضمون ودائم يحتاج جدول تدقيق وMigration لاحقة، مؤجلة دون تطبيق.

اختبارات معزولة تحمي اللغة وطول الملخص واستثناء الاختصار ومسارات الإنشاء والتحديث والنشر القديم، وأصل النص وسجل الحذف وواجهة الإدارة. لا AI مدفوع أو أخبار إنتاج تجريبية أو خدمة جديدة أو Migration أو تغيير أسرار.
