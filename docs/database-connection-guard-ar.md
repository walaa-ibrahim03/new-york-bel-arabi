# الحارس الدائم وخطة التحقق المرحلي

هذا التغيير مبني على ac738f07، ويُجهّز محليًا فقط. لا Migration أو اتصال قواعد أو Push أو Merge أو Deploy أو تغيير متغيرات Vercel أثناء تجهيزه.

## الحارس قبل Prisma

`lib/database-guard.ts` يطابق المضيف الإنتاجي الذي قُرئ مباشرة من Neon Console واسم قاعدة neondb. نقطة الاتصال الصحيحة تحتوي الرقم **1** في b51ufwbz، وليس الحرف l. الاتصال المباشر والمجمّع إلى النقطة نفسها مقبولان، مع TLS وبيانات دخول موجودة ومنفذ PostgreSQL المعتاد. يُرفض تغيير الوجهة عبر معلمات URL أو schema أخرى أو معلمات مكررة.

- MATCH: الهدف يطابق الضوابط.
- MISMATCH: الرابط مقروء لكن الهدف أو ضوابطه تختلف.
- UNVERIFIABLE: الرابط مفقود/غير قابل للتحليل أو ملف البيئة التشغيلي غير معروف.

`lib/prisma.ts` يؤجل إنشاء العميل إلى أول عملية فعلية، ثم يستدعي الحارس قبل الإنشاء ويمرر الرابط المعتمد صراحة إلى Prisma. لا يعود إلى datasource بديلة. MISMATCH وUNVERIFIABLE يرميان خطأ عامًا دون إنشاء عميل. تُفحص الهوية مجددًا قبل كل عملية، حتى عند وجود عميل مخبأ داخل الوحدة.

السجل الوحيد للحارس هو `[database-guard] MATCH` أو MISMATCH أو UNVERIFIABLE؛ لا روابط أو مضيفون أو بيانات دخول. تُحجب رسائل أخطاء Prisma الخام ويُحفظ فقط رمز خطأ Prisma عند توفره، لاستمرار معالجة الرابط المكرر مثل P2002.

أضيف await connection() إلى الصفحة الرئيسية قبل الاستعلام وفق دليل Next المثبت. لذلك لا يلمس البناء قاعدة أو يطبع MATCH مضللًا أثناء التوليد؛ التحقق التشغيلي يحدث عند طلب حقيقي. لا تغيير في تصميم الصفحة.

الحارس يثبت وجهة الاتصال المهيأة من runtime إلى نقطة Neon المؤكدة، ولا يستعلم لإثبات اسم مشروع Neon أو صلاحية كلمة المرور. لا تُستنتج الهوية من عدد الأخبار.

## وضع القراءة فقط

المتغير `NYBA_NEWS_MODE` يقبل تفعيل الكتابة فقط بالقيمة الدقيقة `read-write`. أي قيمة أخرى، أو غياب المتغير، تعني القراءة فقط. لا تُستمد هذه القيمة من طلب مستخدم، ولا توجد API لتبديلها.

في وضع القراءة فقط:

- تُرفض كل إجراءات إنشاء/حفظ/حذف/نشر/مراجعة/اعتماد/إلغاء نشر الأخبار على الخادم قبل التوثيق أو الموارد الخارجية.
- تُرفض دوال استيراد RSS وجلبه وترجمة OpenAI قبل أي طلب شبكة أو إنشاء عميل OpenAI؛ يشمل ذلك استدعاء الدوال مباشرة.
- يُسمح لPrisma بعمليات نموذج القراءة المعروفة فقط: findUnique/findFirst/findMany/count/aggregate/groupBy ونظائر orThrow.
- كل قراءة تُنفّذ داخل معاملة PostgreSQL عليها SET TRANSACTION READ ONLY كطبقة حماية إضافية.
- كل عمليات الكتابة وSQL الخام والمعاملات المخصصة تُرفض قبل الوصول إلى العميل.
- لا تغيير في صلاحيات حساب قاعدة البيانات؛ الحماية يفرضها التطبيق ومعاملات قراءاته. لا تمتد هذه السياسة إلى Prisma CLI أو سكربتات الإدارة المنفصلة، التي لا تُشغّل أثناء التحقق المرحلي.

## الاختبار المحلي المعزول

المشغّل المعزول يظل يقرأ .env.test.local وحده. أصبح يستخدم **الحارس وطبقة Prisma الفعليين** بدل كتابة عميل بديل يتجاوز الحارس في النسخة المؤقتة.

يمرر المشغّل إلى عمليته فقط:

- NYBA_DATABASE_PROFILE=isolated-test.
- NYBA_TEST_DATABASE_URL والمضيف المؤكد من إعدادات الاختبار.
- NYBA_TEST_PROJECT_CONFIRMED=true بعد نجاح فاحص الملف السابق.
- NYBA_NEWS_MODE=read-write لإتاحة الاختبارات الوهمية على nyba_test.

يتطلب الحارس قاعدة nyba_test ومضيف اختبار مطابقًا ومختلفًا عن نقطة الإنتاج. يرفض ملف isolated-test إذا كان NODE_ENV=production أو وجدت متغيرات تشغيل Vercel؛ فلا يمكن استخدامه كتجاوز لحارس الإنتاج. Mock الترجمة وتعطيل RSS في المعاينة المحلية باقيان كما سبق. لا تغيير لأي ملف أسرار محلي.

## خطة نشر مرحلي لاحقة — لم تُنفذ

1. نشر Commit الحارس الجديد على مشروع Vercel الصحيح بإعدادات Production الحالية، دون استبدال DATABASE_URL، وبـ `--prod --skip-domain`. يُمرر NYBA_DATABASE_PROFILE=production وNYBA_NEWS_MODE=read-only على مستوى النسخة الجديدة فقط. لا تُحوّل النطاقات الرسمية ولا تُشغّل Migration تلقائية.
2. طلب الصفحة الرئيسية من النسخة الجديدة وقراءة **سجلات runtime الخاصة بمعرّف Deployment نفسه** بعد الطلب؛ لا نستخدم سجلات البناء دليلًا. المتوقع MATCH فقط. لا تُستدعى أزرار الاستيراد/الترجمة أو عمليات كتابة؛ حمايتها مثبَتة باختبارات آلية. قبل Migration قد تتعذر صفحات تحرير تعتمد أعمدة لم تُضف بعد؛ الصفحة الرئيسية تستخدم الحقول القديمة وتكفي لتشغيل الحارس.
3. عند MISMATCH أو UNVERIFIABLE أو غياب دليل runtime، نتوقف ولا نرقّي النسخة ولا نعدّل الاتصال أو قاعدة البيانات. الموقع السابق يظل على نطاقه. إثبات النسخة الجديدة لا يثبت اتصال النسخة القديمة بأثر رجعي.
4. عند MATCH وبعد إذن تطبيق الإنتاج، نثبت توقف التحرير مؤقتًا في النسخة التي تستقبل الزيارات، ونحدّث النسخة الاحتياطية إذا تغيّرت البيانات، ثم نطبّق Migration الإضافية الوحيدة على الهدف المؤكد ونراجع سلامة الأخبار.
5. يمكن ترقية النسخة المقروءة فقط لتجميد الكتابة بعد نجاح MATCH، لكن ذلك يتطلب قرارًا صريحًا بأن الموقع الجديد سيظل للقراءة فقط. لا يكفي الحارس في النسخة غير المرقاة لإيقاف تحرير النسخة القديمة؛ لا ندعي تجميد الإنتاج بمجرد إنشاء نسخة مرحلية.
6. إعادة السماح بالتحرير تحتاج **نسخة أخرى من Commit نفسه** بـ NYBA_NEWS_MODE=read-write؛ متغيرات Vercel مرتبطة بكل Deployment ولا تتحول قيمة النسخة القديمة عند تغيير إعداد للمستقبل. تُنشأ هذه النسخة أيضًا دون تحويل النطاق، ويُتحقق من MATCH مجددًا قبل ترقيتها. لا يوجد تبديل عام أو تلقائي للوضع.
7. نقطة الرجوع هي نسخة Production السابقة المحفوظة قبل تحويل النطاق. يبقى مخطط القاعدة الإضافي وبياناته؛ لا حذف أعمدة أو استعادة تلقائية تفقد أخبارًا أحدث. الرجوع إلى الكود السابق يعيد سلوكه القديم، لذلك تبقى عمليات التحرير متوقفة إداريًا إلى أن تُراجع الحالة.

النسخة المرحلية تشارك قاعدة الإنتاج **للقراءة بعد MATCH فقط**؛ ليست قاعدة اختبار. لا توجد نقطة تشخيص عامة، ولا تُطبع أسرار أو مضيفون. لا نعتبر نجاح البناء أو تطابق 21 خبرًا إثباتًا لهوية اتصال runtime.

## الفحوص المحلية

الاختبارات تغطي MATCH للاتصال المباشر والمجمّع، MISMATCH للنقطة والقاعدة والخطأ 1/l وTLS ومعلمات تبديل الوجهة، UNVERIFIABLE للرابط المفقود/المعيب، عدم إنشاء العميل عند الرفض، تعقيم الأخطاء والسجلات، معاملات القراءة فقط وحجب SQL الخام والكتابة، وحجب كل إجراءات الأخبار وRSS وOpenAI دون لمس الموارد. وتشمل نجاح ملف الاختبار المحلي ورفضه على Vercel، ومطابقة بيئة المشغّل المعزول للحارس الحقيقي.

الاختبارات 22 ناجحة، وفحص TypeScript وESLint وبناء الإنتاج مع فحص CSS ناجحان. جميعها دون اتصال بقواعد حقيقية أو استدعاء OpenAI. لم نعد اختبارات المتصفح اليدوية.
