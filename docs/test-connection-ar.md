# إدخال اتصال الاختبار محليًا دون مشاركته

تم تجهيز `.env.test.local` في جذر المشروع، بصلاحيات 600 (للمستخدم المالك فقط). DATABASE_URL فارغ عمدًا، ولم تُنسخ إعدادات الإنتاج. قاعدة `.env*` الموجودة في .gitignore تستثنيه، وتم التحقق باستخدام git check-ignore. لم يُضف الملف إلى Git.

## خطواتك داخل Neon

1. افتحي مشروع **new-york-bel-arabi-test** نفسه، وتأكدي من اسم المشروع في اللوحة.
2. من Settings → General انسخي **Project ID** إلى TEST_PROJECT_ID في الملف. الاسم وحده قابل للتكرار ولا يكفي لتحديد المشروع.
3. افتحي **Connect** من المشروع نفسه. اختاري الفرع المقصود، وcompute، وقاعدة **nyba_test**، ودور الاختبار. لا تختاري قاعدة neondb الافتراضية أو مشروع الموقع الأصلي.
4. أوقفي **Connection pooling** للحصول على رابط مباشر؛ المضيف ينبغي ألا يحتوي -pooler. انسخي رابط PostgreSQL فقط، وليس أمر psql ولا سطر shell كاملًا.
5. افتحي `.env.test.local` في محرر محلي، والصقي الرابط بين علامتي الاقتباس في DATABASE_URL. احتفظي بمعلمات TLS التي أنشأتها Neon، ومنها sslmode=require. يدعم الفحص أيضًا channel_binding وconnect_timeout؛ يرفض أي معلمات غير معتمدة بدل تجاهلها.
6. ضعي اسم المضيف وحده في TEST_DATABASE_HOST: يبدأ عادة بـ ep- وينتهي بـ .neon.tech، دون بروتوكول أو اسم مستخدم أو كلمة مرور أو مسار. طابقيه مع نقطة الاتصال الظاهرة في مشروع الاختبار، ولا تنسخيه من إعدادات الإنتاج.
7. اتركي TEST_DATABASE_NAME="nyba_test" وTEST_PROJECT_NAME="new-york-bel-arabi-test". بعد مطابقة Project ID والمضيف والقاعدة في Console غيّري TEST_PROJECT_APPROVED من false إلى true، ثم احفظي الملف.
8. لا ترسلي الرابط في المحادثة أو لقطة شاشة أو أمر Terminal. لا تضيفيه إلى .env أو .env.local أو أي إعداد نشر.

مرجع الخطوات: [Neon: اختيار الفرع والقاعدة والدور ونسخ رابط مباشر من Connect](https://neon.com/docs/connect/connect-from-any-app).

## فحص محلي بلا اتصال

من جذر المشروع:

```sh
npm run check:test-env
```

هذا الأمر يقرأ `.env.test.local` وحده عبر dotenv.parse، دون تحميل .env ودون استخدام أو تغيير process.env.DATABASE_URL. لا يستورد Prisma، ولا يفتح شبكة، ولا ينفّذ SQL أو أوامر فرعية، ولا يعرض الرابط أو كلمة المرور أو تفاصيل الخطأ الخام.

يفحص قاعدة nyba_test بالاسم الدقيق، واسم المشروع ومعرّفه المحلي، وتأكيدك اليدوي، ومطابقة مضيف الرابط مع TEST_DATABASE_HOST، والاتصال المباشر وTLS. يفشل إذا بقي الرابط فارغًا، ولا يرجع إلى رابط الإنتاج. فشل الفحص الحالي متوقع لأن الرابط ومعرّف المشروع لم يُدخلا بعد.

**حدود الفحص:** رابط PostgreSQL لا يثبت اسم مشروع Neon أو ملكية المضيف له. هذا فحص إعداد محلي ومطابقة مع تأكيدك في Console؛ ليس مصادقة للاتصال أو تحققًا عن بُعد من Project ID. لا يمكنه إثبات الفرق عن الإنتاج إذا أُدخل مضيف الإنتاج وأُكد يدويًا خطأً. لذلك مطابقة الهوية من المشروع المستقل إلزامية. فحص اتصال فعلي أو تحقق API يحتاج موافقة مستقلة، ولم يُنفّذ.

## لا تشغلي التطبيق أو Prisma الآن

وجود هذا الملف لا يعيد توجيه أوامر dev/start/Prisma الحالية تلقائيًا إلى الاختبار. لا تستخدمي تلك الأوامر ولا test-import-rss.ts ولا تحمّلي الملف بأمر source. سنجهز لاحقًا مشغّلًا مخصصًا يفرض هدف الاختبار قبل السماح بأي اتصال، بعد موافقتك. هذه الخطوة تقتصر على إدخال الإعداد وفحصه محليًا.

## التحقق المنفذ

- استثناء الملف من Git مؤكد، وصلاحياته 600.
- عشرة اختبارات محلية ناجحة، بما فيها رفض القاعدة الخطأ والمضيف غير المطابق وعدم التأكيد وغياب الرابط، دون الرجوع للإنتاج.
- ESLint للسكربت والاختبارات وgit diff --check ناجحان.
- لم نفتح اتصالًا ولم نشغّل Migration أو db push أو أي كتابة إلى قاعدة.
