# إصدار المرحلة الأولى — جاهز للمراجعة المحلية دون نشر

الفرع: `codex/phase-one-news-review`. التاريخ: 15 أكتوبر 2026.

## ما يدخل الإصدار

- فصل الأصل الإنجليزي في حقول اختيارية دون حذف بيانات قديمة أو ملئها بنص قد يكون ترجمة.
- مسار مراجعة واعتماد ونشر محمي على الخادم، مع إلغاء الاعتماد عند التحرير ومنع حفظ نسخة قديمة.
- التصنيفات المشتركة والأسماء التاريخية، والتحقق من بيانات RSS والروابط.
- ملف Migration إضافي فقط، دون تشغيله في تجهيز الإصدار.
- الاختبارات الآلية والبيانات الخيالية وأدوات الاختبار المعزولة والتوثيق، بوصفها أدوات تطوير لا تُستدعى من التطبيق أو build.

## إصلاح بناء الإنتاج

كان إعداد Tailwind مقتصرًا على محوّل Turbopack، وتعذّر استخدامه هنا بسبب منع فتح منفذ محلي حتى بعد إعادة المحاولة خارج العزل. أصبحت عملية `npm run build` الفعلية:

```sh
prisma generate && next build --webpack
```

أُضيفت إضافة `@tailwindcss/postcss` الرسمية بالإصدار 4.3.3 المتوافق مع إصدار Tailwind المثبت، مع `postcss.config.mjs` وملف القفل المحدث. أُزيلت قاعدة محوّل Turbopack الخاصة من next.config.ts لتجنب المعالجة المزدوجة. لم يتغير app/globals.css أو تصميم الصفحة بسبب هذا الإصلاح. يظل محوّل turbopack اعتمادًا لأداة المعاينة المعزولة فقط.

هذا الإصلاح جزء من كود فرع العمل؛ لم تتغير إعدادات مشروع Vercel أو Google OAuth ولم يحدث نشر.

## الفحوص المعتمدة

- `npm run test:phase-one`: 13 اختبارًا محليًا ناجحًا، دون شبكة أو قواعد بيانات.
- `npm run typecheck:offline`: ناجح.
- `npm run lint`: ناجح على المشروع كله، مع استبعاد عميل Prisma المولد من فحص المصدر.
- `npm run build:check`: ينفّذ npm run build الفعلي دون Mock أو تغييرات للصفحات، ثم يفحص CSS النهائية داخل .next/static.
- تأكد وجود أصناف grid والحواف والألوان والشبكة المتجاوبة وinput-style، وعدم بقاء تعليمات Tailwind غير معالجة. ناتج CSS واحد مولّد بنجاح.
- `git diff --check`: ناجح.

فحص البناء يبدأ ببيئة صغيرة دون مفاتيح أو أسرار موروثة، ويضع DATABASE_URL بقيمة غير صالحة عمدًا. preload يحجب قراءة ملفات .env* ويجعلها غير موجودة لهذه العملية فقط. توليد Prisma محلي ولا يتصل بقاعدة. قد يحتاج بناء الخط Cairo إلى شبكة أو نسخة مخبأة؛ ليس هناك مفتاح OpenAI أو OAuth أو اتصال صالح بقاعدة أثناء الفحص.

ظهر تحذير محلي بأن package-lock.json في المجلد الأب خارج المستودع تم تجاهله؛ لم يمنع البناء، ولا يوجد سبب لتضمين هذا الملف الخارجي في الإصدار.

## الاستبعادات وحماية الأسرار

- .env و.env.local و.env.test.local وكل .env* مستثناة من Git، ولم تُضف للإصدار.
- app/generated/prisma و.next وملفات tsbuildinfo والسجلات ونتيجة docs/news-cycle-result.json ملفات محلية مولدة غير داخلة في Commit.
- النسخ المؤقتة وصور التحقق خارج المستودع؛ يُستثنى أيضًا أي nyba-browser-test-* داخل جذره.
- تبقى نتائج الاختبارات الوصفية اللازمة في Markdown وبيانات fixture الخيالية وأكواد الاختبارات في Git. لا يوجد seed تلقائي أو Migration تلقائية أو تحميل Mock في التطبيق الأصلي.
- فحص الأسرار المحلي يقارن القيم الحساسة دون طباعتها ويفحص أنماط المفاتيح وروابط الاتصال في الملفات المرشحة والـstaging. لا يُعد ضمانًا ضد كل نمط غير معروف.

## ما لم يحدث وما يلزم لاحقًا

لم تُعدّل قاعدة الإنتاج أو الاختبار في مهمة تجهيز هذا الإصدار. لم تُشغّل Migrations أو db push أو اختبارات التكامل التي تكتب للقاعدة. لم تُكرر اختبارات المتصفح اليدوية، ولم يحدث Push أو Merge أو Deploy.

قبل الإنتاج يلزم إذن منفصل لفحص هويته وسجل Migration للقراءة فقط، وتجهيز نسخة احتياطية وإصدار رجوع، وتجميد التحرير مؤقتًا، ثم تطبيق Migration الإضافية المقصودة قبل نشر الكود الجديد. عند أي اختلاف في السجل نتوقف قبل الكتابة. الرجوع يكون لإصدار التطبيق السابق مع إبقاء الأعمدة والبيانات الجديدة، دون حذفها أو استعادة قاعدة أقدم بما يفقد أخبارًا أحدث. يبقى التحرير متوقفًا عند الرجوع لأن الإصدار السابق لا يفرض نظام الاعتماد الجديد.
