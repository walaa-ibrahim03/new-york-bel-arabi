# تشخيص OpenAI 403 — دون توليد مدفوع أو نشر

الفحص للقراءة فقط على الاعتماد المحلي في .env، دون عرض قيمته أو تعديله. لا اتصال قاعدة بيانات. لا يفترض هذا الفحص أن مفتاح Vercel Sensitive مطابق للمفتاح المحلي؛ لم تُقرأ قيمته أو تُستبدل.

- المفتاح موجود، دون مسافات خارجية. لا OPENAI_NEWS_MODEL محليًا؛ الافتراضي gpt-5.1 لم يتغير. لا OPENAI_BASE_URL أو OPENAI_ORG_ID أو OPENAI_PROJECT_ID محليًا، فيستخدم SDK العنوان الرسمي والمشروع المرتبط بالمفتاح، بلا ترويسات مشروع إضافية.
- الطلب السابق كان GET /v1/models/gpt-5.1 لبيانات نموذج واحد، وليس طلب توليد ولا طلب قائمة النماذج. طريقته صحيحة وتوافق Models.retrieve في SDK المثبت.
- الرد 403 يذكر صراحة Missing scopes: api.model.read. السبب المثبت هو افتقاد صلاحية قراءة بيانات النموذج في الاعتماد/الدور الفعّال. الرد العام يذكر أدوار المؤسسة والمشروع والمفتاح المقيد كاحتمالات؛ لا يحدد أي طبقة بالضبط فرضت القيد. لا دليل من الرد على خطأ اسم النموذج أو انتهاء صلاحيته أو سوء توجيه المشروع.
- لا يُستنتج من هذا الرد أن POST /v1/responses سيفشل. صلاحيات العملية مختلفة، ولم نرسل طلب توليد أو نوسع صلاحيات المفتاح لمجرد نجاح فحص Models.
- يمكن التحقق الفعلي باختبار ترجمة وتبسيط بنصين خياليين قصيرين عبر Responses بالنموذج الحالي فقط، دون قاعدة بيانات أو أخبار حقيقية. يتطلب ذلك موافقة مستقلة على التكلفة قبل التنفيذ. يمكن خفض max_output_tokens إلى 150 لكل اختبار مع reasoning=none وmaxRetries=0؛ التكلفة المتوقعة أقل من سنت أمريكي للطلبين حسب تعرفة gpt-5.1 الحالية، وهي تقدير وليست فاتورة أو حد إنفاق مفروض من المزود. لم يُنفذ الاختبار.

## جاهزية النشر

يمكن نشر التحرير اليدوي وSEO دون انتظار صلاحية Models. زرا الترجمة والتبسيط باقيان، ولم يُربط تعطيلهما بنتيجة فحص Models. عند فشل طلب توليد فعلي، تعرض إجراءات المحرر والموجز رسالة عربية آمنة تميز رفض الوصول، وعدم تهيئة الخدمة، وعدم الوصول للنموذج، وحد الطلبات/الرصيد، وتعذر الاتصال/الخدمة، وتؤكد استمرار التحرير اليدوي وSEO وعدم الحفظ أو النشر. لا تُعاد رسالة المزود الخام أو معرفاته للمستخدم.

لا Migration مطلوبة. لا تغيير DATABASE_URL أو مخطط Prisma أو الحارس أو الأخبار أو إعدادات الإنتاج، ولا Deploy. لا تفعيل AI مجدول أو نموذج بديل أو استهلاك مدفوع. يستلزم النشر موافقة المستخدم بعد إبلاغه بنتيجة التشخيص؛ نجاح التوليد الحقيقي يظل غير مؤكد قبل الاختبار المصرح به.

لم تُكرر الاختبارات الستون كاملة. شُغلت اختبارات المحرر الثمانية المستهدفة دون شبكة أو قاعدة أو API، وأضيف فحص لخطأ 403 والرسائل الآمنة واستقلال SEO عن AI. فحوص البناء/TypeScript وESLint تُجرى للتغيير الفعلي في معالجة الأخطاء.

المراجع: [صلاحيات مفاتيح المشروع](https://help.openai.com/en/articles/9186755-managing-projects-in-the-api-platform)، [أخطاء API](https://developers.openai.com/api/docs/guides/error-codes)، [تعرفة النموذج](https://developers.openai.com/api/docs/models/gpt-5.1).

النتيجة: الاختبارات الثمانية المستهدفة وESLint للملفات المعدلة وTypeScript وبناء الإنتاج مع CSS وgit diff --check نجحت. فحص أنماط الأسرار للتغييرات نجح. لم تُكرر مجموعة الاختبارات الكاملة.
