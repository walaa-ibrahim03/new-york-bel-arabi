# تقرير اختبار دورة الأخبار على nyba_test

التاريخ: 15 أكتوبر 2026. الفرع: `codex/phase-one-news-review`.
النتيجة: **14 اختبارًا ناجحًا، صفر فشل**.

## العزل وطريقة الاختبار

استخدم المشغّل `scripts/test-news-cycle.cjs` إعدادات `.env.test.local` وحدها عبر parse دون تحميل .env. تحقق من الاسم الدقيق nyba_test والمضيف المباشر المؤكد يدويًا وTLS، وفحص اسم القاعدة الحالي وسجل Migrations الأربعة وبصماتها قبل إنشاء البيانات. أعاد قراءة إعداد الهدف قبل كل كتابة، ونفّذ فحص current_database() داخل معاملة الكتابة نفسها. أُعطي Prisma عنوان الاختبار صراحة، وأُزيلت أسرار البيئة الموروثة من عملية الاختبار، ولم يُستخدم اتصال افتراضي.

حُمّل كود إجراءات الخادم الأصلي من actions.ts وeditor-actions.ts، وكود الاستيراد والسياسات الفعلي، عبر TypeScript transpilation. قاعدة البيانات وقيودها وعملياتها حقيقية على الاختبار. استُبدلت جلسة المستخدم وNext redirect/cache وناقل RSS وخدمة الترجمة بأدوات Mock محددة. يرفض محمّل الاختبار أي اعتماد خارجي غير مسموح به، ولا يحمّل lib/prisma.ts أو auth.ts أو OpenAI الحقيقي. هذا اختبار تكامل للكود على الخادم مع قاعدة فعلية؛ لا يشمل النقل عبر HTTP أو تسجيل الدخول الحقيقي أو العرض في المتصفح.

تعذر الاتصال من داخل عزل الشبكة، ثم نُفذت الدورة بنجاح خارج قيد الشبكة. لم يحدث تغيير في كود التطبيق أو المخطط خلال هذه المهمة.

## النتائج لكل اختبار

| الاختبار | النتيجة والأدلة |
| --- | --- |
| 1. الاستيراد والتحقق | نجح: استُورد خبر وهمي واحد كمسودة، وصُنّف «الهجرة والإقامة»، وحُفظ العنوان والملخص والمحتوى الأصلي منفصلًا. تم تجاوز ثلاثة عناصر مكررة/غير صالحة واحتساب عنصر غير ذي صلة. |
| 2. منع التكرار | نجح: أُعيد استيراد الرابط نفسه؛ لم يُنشأ خبر ثانٍ وبقي العدد للرابط واحدًا، عبر قيد sourceUrl الحقيقي في القاعدة. |
| 3. منع النشر المباشر | نجح: استدعاء publishArticle مباشرة من مسودة رُفض على الخادم، وبقيت المسودة كما هي. |
| 4. الترجمة الوهمية | نجح: translateArticle قرأ الأصل المحفوظ، وأعاد Mock العربية دون حفظ ضمني أو تغيير سجل الخبر. نداء Mock واحد، ولا استدعاء لخدمة OpenAI. |
| 5. فصل الأصل عن العربية | نجح: حُفظ العنوان والمحتوى العربيان عبر updateArticle، وبقيت حقول الأصل الثلاثة دون تغيير، حتى عند إرسال حقل originalTitle مزور ضمن FormData. |
| 6. دورة المراحل | نجح: DRAFT → IN_REVIEW → APPROVED → PUBLISHED. تأكد وقت المراجعة والاعتماد وهوية المدير الوهمية وتاريخ النشر. رُفض النشر من IN_REVIEW أيضًا. |
| 7. إلغاء النشر والاعتماد | نجح: إلغاء النشر أعاد المسودة ومسح تاريخ النشر والاعتماد. بعد الاعتماد مجددًا ثم التحرير أُلغي الاعتماد والمراجعة وتاريخ النشر، وبقي الأصل ثابتًا ورُفض النشر المباشر مجددًا. |
| 8. منع حفظ نسخة قديمة | نجح: تعديل أول رفع رقم النسخة؛ محاولة ثانية بالنسخة القديمة رُفضت وبقي نص النسخة الحديثة. |
| 9. الروابط والتصنيفات | نجح: رُفض javascript وعنوان IP محلي ورابط يحوي بيانات دخول وتصنيف مجهول جديد، ورُفض تغيير مصدر خبر ذي أصل محفوظ. لم يتغير السجل بهذه المحاولات. |
| 10. صلاحيات الخادم | نجح: مستخدم Mock غير المدير لم يستطع إرسال المراجعة أو النشر أو الحفظ أو الترجمة. |
| 11. خبر قديم بلا أصل | نجح: أُنشئ سجل دون حقول الأصل فبقيت NULL، ثم حُرر ونُشر بعد المراجعة والاعتماد. تصنيف «الهجرة» طُبع إلى «الهجرة والإقامة». الترجمة الآلية رُفضت دون زيادة عدد نداءات Mock. |
| 12. تصنيف قديم مجهول | نجح: بقي التصنيف التاريخي محفوظًا أثناء التحرير؛ منع الخادم إرساله للمراجعة إلى أن اختير تصنيف مدعوم، ثم نجح الإرسال. بقي «سكن واقتصاد» مدعومًا كما هو. |
| 13. منشور قديم بلا اعتماد تاريخي | نجح: أُنشئ سجل وهمي بحالة منشور دون أصل أو اعتماد تاريخي. حُفظت حالته عند القراءة، وعند تحريره عاد للمسودة وأُلغي تاريخ النشر، ولم يُسمح بإعادة نشره مباشرة. |
| 14. حماية البيانات الأخرى | نجح: قورنت بصمة جميع السجلات السابقة قبل الاختبار وبعده، واستُثنيت فقط المعرّفات التي أنشأها المشغّل لهذه المهمة. لم تتغير أي سجلات أخرى، والزيادة تساوي السجلات الأربعة المنشأة فقط. |

## الأخطاء والحدود

لم تُكتشف أخطاء وظيفية ضمن الاختبارات الأربعة عشر. رفض الأخبار القديمة بلا أصل للترجمة الآلية ورفض التصنيف التاريخي المجهول عند بدء المراجعة هما سلوكان مقصودان لحماية الأصل وضمان مراجعة التصنيف، مع بقاء التحرير اليدوي متاحًا.

لا تثبت هذه الاختبارات عمل Google/OAuth أو واجهة المتصفح أو تحميل RSS من الشبكة أو جودة ترجمة OpenAI. استُخدمت بيانات خيالية وMock فقط لهذه الخدمات، وفق الموافقة. توافق الخبر القديم هنا اختبار سجل ذي أصل NULL داخل المخطط الجديد، وليس إعادة تطبيق Migration على قاعدة ذات مخطط قديم.
