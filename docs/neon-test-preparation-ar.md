# تحضير اختبار Neon مستقل — دون تنفيذ

التاريخ: 15 أكتوبر 2026. الفرع: `codex/phase-one-news-review`.
هذه خطة وتحضيرات محلية فقط. لم يُنشأ مشروع أو قاعدة، ولم يحدث اتصال بقاعدة، ولم تُطبّق Migration أو db push. لا نشر أو Push أو Merge.

## مراجعة SQL

الملف: `prisma/migrations/20261015160000_original_text_and_review/migration.sql`.

تعليمة ALTER TABLE واحدة تضيف ثمانية أعمدة. حقول originalTitle وoriginalSummary وoriginalContent وreviewedAt وreviewedBy وapprovedAt وapprovedBy اختيارية وتبدأ NULL. العمود revision إلزامي بقيمة افتراضية 0، ولذلك تظهر السجلات السابقة بقيمة 0 فيه. هذا تغيير إضافي للمخطط؛ لا يعيد كتابة نصوص الأخبار ولا ينقل الترجمات إلى الأصل ولا يغير حالة النشر أو التصنيف أو الرابط. لا DELETE أو UPDATE أو INSERT أو DROP أو TRUNCATE أو تغيير نوع أو اسم عمود قائم. قد يأخذ ALTER TABLE قفلًا؛ يجب اختباره قبل الإنتاج.

الاختبار المحلي يثبت أسماء الأعمدة وعددها واختياريتها وعدم وجود أوامر حذف أو تحديث. لا يشغّل SQL. ليس ذلك بديلًا عن اختبار التطبيق على PostgreSQL لاحقًا.

راجعنا أيضًا الملفات السابقة: إنشاء الجدول، إضافة حقول العرض، ثم فهرس sourceUrl الفريد. عند تطبيق السجل كاملًا على قاعدة الاختبار الفارغة لن توجد تعارضات بيانات. Migration الفهرس السابقة قد تفشل مع روابط مكررة في قاعدة قائمة؛ لا نفترض حالة الإنتاج ولا نفحصها في هذه المرحلة.

## الأوامر المعتمدة الآن

```sh
npm run test:phase-one
npm run typecheck:offline
git diff --check
```

الأمران الأولان يستخدمان `scripts/check-offline.cjs`: ينشئ بيئة فرعية بقائمة سماح صغيرة لمتغيرات النظام، ولا يمرر DATABASE_URL أو OPENAI_API_KEY أو أسرار التوثيق الموروثة. يضع DATABASE_URL بقيمة غير صالحة ويحمّل مانع شبكة يمنع TCP وTLS وHTTP وfetch. الاختبارات تستخدم أدوات وهمية وتحمّل الاعتماديات المحلية المسموحة فقط؛ لا تحمل dotenv أو Prisma الحقيقي. لا تُقرأ .env في هذه الاختبارات. فحص TypeScript لا ينفّذ التطبيق أو Prisma.

لا تشغّل `node --test` العام؛ لأنه قد يلتقط ملفات تجريبية خارج المجموعة الآمنة. لا تستخدم `test-import-rss.ts`: يحمّل Prisma الحقيقي ويستدعي create، ويمكنه الكتابة للهدف الذي يشير إليه DATABASE_URL. ملف `test-rss.ts` يجلب RSS حقيقيًا ويطبع عناصره، وليس اختبارًا معزولًا. `npm run dev` و`npm start` يشغّلان تطبيقًا قادرًا على الاتصال بالقاعدة؛ لا يُستخدمان مع البيئة الحالية للاختبار.

`npm run build` ليس أمر اختبار معزولًا بذاته: Prisma config يستورد dotenv، وNext يقرأ ملفات .env، وقد يتطلب البناء شبكة لتحميل الخطوط. نجاح بناء Webpack السابق كان مع استبدال DATABASE_URL صراحة. لا تعتبر البناء الخام أو prisma validate/generate ضمانًا لعزل البيئة، ولا تشغّل Prisma migrate أو db push الآن.

## إنشاء مشروع Neon لاحقًا — بعد الموافقة فقط

1. افتحي Neon Console ثم صفحة المشاريع واضغطي **New Project**. الاسم المقترح `new-york-bel-arabi-test`.
2. اختاري منطقة مناسبة وإصدار PostgreSQL الموافق للإنتاج من سجلات الإعداد المعروفة أو بمراجعتك في اللوحة؛ لا نحتاج إلى الاتصال بالإنتاج لمعرفة ذلك.
3. اتركي خدمة Postgres وحدها ما لم توجد حاجة أخرى. أنشئي مشروعًا فارغًا مستقلًا، ولا تختاري استيراد بيانات أو نسخ فرع من مشروع الإنتاج، ولا تربطيه تلقائيًا بموقع الإنتاج أو منصة نشره.
4. الفرع الافتراضي داخل المشروع الجديد قد يسمى `production` في Console. الاسم لا يعني أنه قاعدة الموقع؛ العزل هنا بهوية المشروع ونقطة الاتصال. يمكن اختيار اسم واضح مثل `phase-one-test` إذا أتاحت اللوحة إعادة التسمية.
5. استخدمي قاعدة باسم `nyba_test` ودور اختبار منفصل. إن أُنشئت قاعدة افتراضية `neondb`، أنشئي `nyba_test` داخل المشروع الجديد بعد الإذن؛ لا تغيّري أي مورد في المشروع الأصلي.
6. سجّلي هوية المشروع والفرع ونقطة الاتصال واسم القاعدة، ثم طابقيها من صفحة المشروع الجديد. احفظي رابط الاتصال في مدير أسرار أو ملف محلي مستبعد من Git، لا في المحادثة أو لقطة شاشة أو أمر shell يحتوي كلمة المرور. لا تستبدلي .env الخاص بالإنتاج.
7. من **Connect** اختاري القاعدة والدور والفرع الخاصين بالاختبار. جهزي رابطًا مباشرًا غير pooled لأوامر الإدارة اللاحقة، واتصال التطبيق الاختباري منفصلًا عند الحاجة. احتفظي بـ sslmode=require. لا تعرضي الرابط في السجلات.
8. استخدمي أقل موارد مناسبة وراجعي حدود خطتك قبل الإنشاء؛ لا نفترض إتاحة مشروع إضافي مجانًا.

مراجع Neon الرسمية:
- [إنشاء وإدارة المشاريع](https://neon.com/docs/manage/projects)
- [اتصال التطبيقات](https://neon.com/docs/connect/connect-from-any-app)
- [المباشر وpooled](https://github.com/neondatabase/website/blob/main/content/docs/get-started/connect-neon.md)

## منع استخدام الإنتاج لاحقًا

جهزنا `scripts/test-database-target.cjs` كدالة تحقق صرفة لا تقرأ .env ولا تتصل ولا تكتب ولا تطبع الروابط. تتطلب صراحة:

- TEST_PROJECT_APPROVED=true بعد موافقتك ومطابقة المشروع في Console.
- TEST_DATABASE_URL من مشروع الاختبار فقط، بلا رجوع احتياطي إلى DATABASE_URL.
- TEST_DATABASE_HOST مطابق تمامًا لنقطة الاتصال المباشرة المؤكدة يدويًا.
- TEST_DATABASE_NAME=nyba_test، ورابط TLS مباشر دون معلمات تسمح بتغيير الهدف.

ترفض الدالة تطابق نقطة الاختبار مع نقطة DATABASE_URL الحالية، سواء كانت pooled أو مباشرة. هذا فحص دفاعي لا يثبت هوية المشروع من اسم المضيف وحده؛ المطابقة مع Console إلزامية. الدالة مجهزة ومختبرة فقط ولم تُربط بأوامر التطبيق أو Prisma الحالية. ليست لدينا الآن أوامر Migration/Seed معتمدة أو منفذة.

عند الإذن لاحقًا يجب تجهيز مشغّل حصري للاختبار، يتحقق بالدالة أولًا ثم يمرر عنوان الاختبار صراحة إلى العملية الفرعية كـ DATABASE_URL، مع بيئة نظيفة دون أسرار الإنتاج أو ملفات .env الإنتاجية. لا يكفي ضبط TEST_DATABASE_URL وحده لأن التطبيق وPrisma الحاليين يقرآن DATABASE_URL. قبل أي اتصال نعرض العملية المستهدفة ونطلب موافقتك عليها.

## البيانات التجريبية وخطة الاختبار

الملف `tests/fixtures/phase-one.json` بيانات خيالية واضحة العلامة ولا يتضمن سكربت إدخال أو اتصال أو أخبارًا حقيقية.

| التجربة | المدخل | النتيجة المتوقعة |
| --- | --- | --- |
| استيراد | خبر RSS عن ورشة خيالية للهجرة | مسودة جديدة، أصل إنجليزي محفوظ منفصلًا |
| تكرار | العنصر نفسه والرابط نفسه | تجاوز المكرر، دون مسح الخبر الأول |
| رابط غير صالح | javascript | رفض العنصر |
| تاريخ غير صالح | not-a-date | رفض العنصر |
| موضوع غير مستهدف | نجوم بعيدة | احتسابه غير ذي صلة |
| ترجمة | ترجمة عربية وهمية مرفقة | عرض العربية وحفظها دون تغيير الأصل |
| مراجعة | المسودة المحفوظة | قيد المراجعة ثم معتمد بهوية المدير ووقت الاعتماد |
| نشر مباشر | محاولة النشر من مسودة أو قيد المراجعة | رفض على الخادم |
| نشر معتمد | خبر معتمد | منشور وله تاريخ نشر |
| تحرير بعد الاعتماد/النشر | تعديل العنوان | مسودة، إلغاء الاعتماد وتاريخ النشر، الأصل كما هو |
| تعارض تعديل | نافذتان ورقم نسخة قديم | رفض الحفظ القديم |
| أخبار تاريخية | ثلاثة سجلات بلا حقول أصل | قبول NULL، الحفاظ على المنشور والتصنيف القديم، وعدم افتراض أصل إنجليزي |

ملف البيانات يُستخدم لاحقًا على المشروع المستقل فقط. لا يمكن تمرير example.org إلى RSS الحقيقي دون مواءمة اختبار: مصادر الجلب في التطبيق مقيدة بالقائمة المعتمدة. يستخدم اختبار الاستيراد الوهمي عناصر الملف بدل فتح جلب لمصدر عشوائي. الترجمة المرفقة هي بديل وهمي؛ لا تختبر خدمة OpenAI. تجربة ترجمة حقيقية تحتاج موافقة منفصلة على النداء الخارجي وكلفته، ومفتاح اختبار منفصل، دون بيانات إنتاج.

لتجربة توافق Migration لاحقًا: في قاعدة الاختبار الفارغة فقط نطبّق أول ثلاث Migrations، ثم ندرج legacyArticles التجريبية دون أعمدة الأصل؛ نسجل عددها وقيمها، ثم نطبّق الجديدة ونقارن العدد والحقول السابقة وأن الأصل NULL وrevision=0. لا نضيفها بعد الجديدة فقط، لأن ذلك لا يختبر ترقية سجل موجود. نكمل تجربة الاستيراد والترجمة الوهمية والمراحل ثم اختبارات الواجهة. كل هذه خطوات مستقبلية تتطلب الإذن وليست منفذة.

## الأسرار والسجلات

- لا تطبعي متغيرات البيئة أو روابط الاتصال أو كائنات أخطاء Prisma الخام أو إعدادات OpenAI. عند إعداد مشغّل الاختبار لاحقًا تُطبع أسماء المراحل والأعداد ورسائل عامة فقط.
- .env* وملفات المفاتيح المحلية تُبقى خارج Git؛ لا يُنشأ ملف إعداد حقيقي في هذا التحضير.
- فحص محلي دون طباعة القيم راجع ملفات العمل غير المستبعدة، الفرق المرحلي وسجل Git المتاح، وقارن القيم الحساسة الموجودة محليًا وأنماط مفاتيح وروابط اعتماد معروفة. راجعنا أيضًا ملفات السجلات المحلية الظاهرة في جذر المشروع و.next؛ لم توجد ملفات log فيها. لا يشمل الفحص سجل الطرفية الخارجي أو خدمات بعيدة، ولا يثبت غياب كل نمط سر غير معروف.

## نتيجة التحضير

تسعة اختبارات معزولة ناجحة، وفحص TypeScript المعزول ناجح، وESLint لسكربتات التحضير والاختبارات ناجح، وgit diff --check ناجح. الفحص النهائي راجع 58 ملفًا محليًا مع الفروق المرحلية وسجل Git المتاح؛ لم يجد أنماط أسرار أو تطابقًا مع القيم الحساسة المحلية، ولم توجد ملفات أسرار متتبعة أو ملفات log في المواضع المفحوصة. لم تُنفذ أوامر قاعدة بيانات. ننتظر موافقتك على إنشاء المشروع المستقل، ثم نطلب الإذن المناسب قبل الاتصال وتطبيق المخطط وإدخال بيانات الاختبار. لا تشمل هذه الموافقة الإنتاج أو النشر.
