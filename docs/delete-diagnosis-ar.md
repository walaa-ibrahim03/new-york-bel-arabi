# تشخيص الحذف وإصلاح رسائل نتيجته

## السبب المؤكد وحدود التشخيص

فحص Vercel للقراءة فقط أكد أن النطاق الرسمي ما زال على الإصدار `dpl_6Mro9xq6BDBmVWo2Sr2kUcEyq9SU` الذي نُشر عمدًا بوضع القراءة فقط. لذلك يرفض الخادم الحذف قبل المصادقة أو إنشاء اتصال Prisma؛ لا يستلزم ذلك عطلًا في قاعدة البيانات. لم تتغير إعدادات Vercel أو DATABASE_URL.

كانت الواجهة تعرض زر الحذف دون بيان حالة القراءة فقط، وتستبدل جميع أسباب رفضه برسالة عامة في أعلى القائمة، قد تكون خارج الجزء المرئي عند الضغط على خبر أسفل الصفحة. لا دليل على حذف ناجح لم تُحدّثه Prisma؛ لم نحذف أخبار إنتاج لإعادة إنتاج المشكلة.

العملية التي تستمع على localhost:3100 تستخدم لقطة معاينة قديمة منفصلة عن ملفات المشروع الحالية، وبها محول Prisma الاختباري السابق دون الحارس الجديد. فتح /admin في المتصفح المتاح أعاد إلى الصفحة الرئيسية لغياب جلسة مدير. لذلك لم نثبت سبب فشل نقرة بعينها في تلك اللقطة، ولم نفترض أن حارس الإصدار الجديد يعمل داخلها.

## الإصلاح

- ترسل صفحة الإدارة حالة القراءة فقط إلى الواجهة؛ تظهر رسالة واضحة ويتوقف زر الحذف فيها. تبقى حماية الخادم مستقلة عن الواجهة.
- يرجع Server Action نتيجة آمنة ومحددة للقراءة فقط، والصلاحيات، والمعرّف، ورفض الحارس، والخبر غير الموجود، وفشل قاعدة البيانات. لا يرجع رسائل Prisma الخام أو أسرار الاتصال.
- تظهر رسالة الفشل بجوار الخبر، وتبقى رسالة خطأ الشبكة حذرة: أعيدي تحميل الصفحة للتحقق من نتيجة الطلب قبل تكراره.
- عند تأكيد النجاح يُزال الخبر من القائمة المحلية وتُحدّث العدادات وتظهر رسالة نجاح. تُحدّث أيضًا مسارات الإدارة والخبر والرئيسية وخريطة الموقع. فشل تحديث الكاش بعد الحذف لا يُبلّغ المستخدم كأن حذف قاعدة البيانات قد فشل.
- بقي تأكيد الحذف وصلاحيات المدير وحارس الهوية ونظام المراجعة دون تعطيل. لم تُفتح الكتابة على الإنتاج.

## التحقق

- `npm run test:phase-one`: 29 اختبارًا ناجحًا دون شبكة أو قواعد حقيقية، تشمل الحذف على صفوف وهمية في الذاكرة وسلوك الواجهة والصلاحيات والحارس.
- `npm run typecheck:offline`: ناجح.
- `npm run lint`: ناجح.
- `node scripts/test-delete-article.cjs`: ناجح على nyba_test فقط؛ يقرأ .env.test.local حصريًا، وينشئ عملية فرعية ببيئة نظيفة، ويطابق المضيف والحارس ثم current_database() داخل معاملة قراءة قبل أي كتابة. ينشئ خبرًا وهميًا خاصًا بالمهمة، ويختبر منع القراءة فقط والصلاحيات، ثم يحذفه وحده عبر Server Action الحقيقي وطبقة Prisma الحقيقية. جلسة المدير وتحديث كاش Next بدائل اختبار داخل السكربت فقط؛ لم تتغير مصادقة التطبيق. قورنت بصمة جميع الصفوف الموجودة قبل الاختبار وبعده وتطابقت. لا OAuth أو OpenAI أو RSS في هذا الاختبار.

لا تشغّل الاختبار الحي ضمن اختبارات CI العادية؛ هو أمر اختياري صريح يكتب في قاعدة الاختبار المؤكدة فقط. لا Migration أو db push أو Deploy أو Push أو Merge في هذا الإصلاح.

## إظهار الإصلاح

إعادة تشغيل `npm run preview:test` تنشئ لقطة جديدة من الملفات المعدلة؛ العملية المحلية القديمة لا تتحدث تلقائيًا بتعديل ملفات المستودع. لا حاجة لتغيير اتصال الاختبار.

الموقع الرسمي يبقى للقراءة فقط وفق حالة الانتقال السابقة. إتاحة الحذف عليه تحتاج موافقة على نشر الإصلاح وإكمال الانتقال إلى إصدار الكتابة؛ لا يجوز تجاوز الحارس أو تغيير DATABASE_URL لمعالجة ذلك.
